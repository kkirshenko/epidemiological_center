# Полное руководство по запуску приложения на Docker для новичков

## 📋 Что вы узнаете из этого руководства

Это пошаговое руководство написано **для людей, которые никогда не работали с Docker и программированием**. Мы разберём каждый шаг максимально подробно, с объяснением всех терминов.

## 📚 Часть 1: Что такое Docker и зачем он нужен?

### Простыми словами о Docker

Представьте, что вы купили сложный конструктор (это наше приложение). Обычно, чтобы его собрать, нужно:
1. Купить специальные инструменты
2. Найти нужные детали
3. Изучить инструкцию по сборке
4. Потратить много времени на настройку

**Docker** — это как волшебная коробка, в которой уже есть:
- Все необходимые инструменты
- Все нужные детали
- Инструкция по автоматической сборке

Вы просто говорите "запусти коробку" — и всё работает!

### Основные понятия (обязательно прочитайте!)

| Термин | Простое объяснение |
|--------|-------------------|
| **Docker** | Программа, которая создаёт изолированные контейнеры для приложений |
| **Контейнер** | Изолированная "коробка", где работает приложение со всеми своими компонентами |
| **Образ (Image)** | Шаблон или "чертёж" для создания контейнера |
| **Dockerfile** | Инструкция, как собрать образ приложения |
| **docker-compose.yml** | Файл, который описывает, как запустить несколько контейнеров вместе |
| **База данных** | Место, где приложение хранит всю свою информацию (как таблица Excel) |
| **Порт** | "Дверь", через которую можно попасть в контейнер извне |

## 🛠️ Часть 2: Подготовка — установка Docker

### Шаг 1: Проверьте, установлен ли у вас Docker

Откройте терминал (командную строку) и введите:

```bash
docker --version
```

**Если вы видите версию** (например, `Docker version 24.0.7`):
- ✅ Docker установлен! Переходите к Шагу 3.

**Если вы видите ошибку** "команда не найдена" или подобное:
- ❌ Docker не установлен. Переходите к Шагу 2.

### Шаг 2: Установка Docker

#### Для пользователей Windows:

1. Откройте браузер и перейдите на сайт: https://www.docker.com/products/docker-desktop/
2. Нажмите кнопку **"Download for Windows"**
3. Запустите скачанный файл `Docker Desktop Installer.exe`
4. Следуйте инструкциям установщика (нажимайте "Next", соглашайтесь с условиями)
5. После установки перезагрузите компьютер
6. Запустите программу **Docker Desktop** из меню Пуск
7. Дождитесь, пока в нижнем левом углу появится зелёная надпись **"Engine running"**

#### Для пользователей macOS:

1. Откройте браузер и перейдите на сайт: https://www.docker.com/products/docker-desktop/
2. Нажмите кнопку **"Download for Mac"**
3. Выберите версию для вашего процессора:
   - **Apple Silicon** — если у вас Mac с процессором M1, M2, M3
   - **Intel** — если у вас старый Mac с процессором Intel
4. Откройте скачанный файл `.dmg`
5. Перетащите значок Docker в папку **Applications**
6. Запустите Docker из папки Applications
7. Разрешите доступ, если система спросит пароль
8. Дождитесь, пока в верхнем меню появится значок кита 🐳 и надпись **"Engine running"**

#### Для пользователей Linux (Ubuntu/Debian):

Откройте терминал и выполните команды по очереди:

```bash
# Обновляем список пакетов
sudo apt-get update

# Устанавлием необходимые пакеты
sudo apt-get install -y ca-certificates curl gnupg lsb-release

# Добавляем официальный ключ Docker
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# Добавляем репозиторий Docker
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Обновляем список пакетов ещё раз
sudo apt-get update

# Устанавливаем Docker
sudo apt-get install -y docker-ce docker-ce-cli containerd.io

# Проверяем установку
docker --version
```

### Шаг 3: Проверка работы Docker

Введите в терминале:

```bash
docker run hello-world
```

**Что должно произойти:**
1. Docker скачает маленький тестовый образ
2. Запустит контейнер
3. Покажет сообщение: *"Hello from Docker!"*

**Если вы увидели это сообщение** — поздравляю! ✅ Docker работает правильно!

**Если возникла ошибка:**
- Убедитесь, что Docker Desktop запущен (для Windows/Mac)
- Попробуйте перезапустить компьютер
- Для Linux: возможно, нужно добавить пользователя в группу docker:
  ```bash
  sudo usermod -aG docker $USER
  ```
  Затем выйдите из системы и войдите снова.

## 📁 Часть 3: Подготовка файлов приложения

### Шаг 1: Узнайте, где находятся файлы приложения

Файлы, которые нам нужны, уже есть в папке `/workspace`. Вот что там находится:

| Файл | Зачем он нужен |
|------|---------------|
| `Dockerfile` | Инструкция, как собрать приложение |
| `docker-compose.yml` | Инструкция, как запустить приложение вместе с базой данных |
| `database/postgresql/schema.sql` | Структура базы данных (таблицы, поля) |
| `src/` | Исходный код приложения (нам не нужно его трогать) |
| `build.gradle` | Настройки сборки приложения (нам не нужно его трогать) |

### Шаг 2: Откройте терминал в папке с приложением

#### Для пользователей Windows:

1. Откройте **Проводник** (папку с файлами)
2. Перейдите в папку `/workspace` (или туда, где лежат файлы)
3. В адресной строке вверху напишите `cmd` и нажмите Enter
4. Откроется командная строка сразу в нужной папке

**ИЛИ так:**
1. Нажмите правой кнопкой мыши в пустом месте папки
2. Выберите **"Открыть в терминале"** или **"Open in Terminal"**

#### Для пользователей macOS:

1. Откройте **Finder** и перейдите в папку с файлами
2. Нажмите правой кнопкой мыши (или Ctrl+клик) на папке
3. Выберите **"Новый терминал в папке"**

**ИЛИ так:**
1. Откройте программу **Terminal**
2. Напишите `cd `, затем перетащите папку с файлами в окно терминала
3. Нажмите Enter

#### Для пользователей Linux:

Откройте терминал и перейдите в папку:

```bash
cd /workspace
```

### Шаг 3: Проверьте, что все файлы на месте

Введите команду:

```bash

```

Вы должны увидеть файлы:
- `Dockerfile`

**Если файлов нет** — убедитесь, что вы в правильной папке.

## 🚀 Часть 4: Запуск приложения

Теперь самое главное — запускаем приложение!

### Шаг 1: Запуск одной командой

Введите в терминале (в папке с файлами):

```bash
docker compose up --build
```

**Что делает эта команда:**
- `docker compose` — говорит Docker использовать файл `docker-compose.yml`
- `up` — запустить всё, что описано в файле
- `--build` — сначала собрать (скомпилировать) приложение из исходного кода

### Шаг 2: Наблюдайте за процессом

После ввода команды вы увидите много текста. Это нормально! Вот что происходит:

1. **Скачивание образов** (первые минуты):
   ```
   postgres Pulling ...
   eclipse-temurin Pulling ...
   ```
   Docker скачивает готовые компоненты из интернета. Это может занять 5-15 минут в зависимости от скорости интернета.

2. **Сборка приложения**:
   ```
   [+] Building 15/15 DONE
   ```
   Docker компилирует код приложения. Это занимает 3-10 минут.

3. **Запуск контейнеров**:
   ```
   sanepidcenter-db Started
   sanepidcenter-app Started
   ```
   Контейнеры запустились!

### Шаг 3: Дождитесь полной готовности

Приложение готово, когда вы увидите сообщения типа:

```
sanepidcenter-app  | Started SanEpidCenterApplication in 45.123 seconds
sanepidcenter-app  | Tomcat started on port(s): 8080 (http)
```

**Важно:** Первый запуск может занять **10-20 минут**, потому что:
- Скачиваются большие файлы (образы)
- Компилируется код приложения
- Инициализируется база данных

### Шаг 4: Проверьте, что всё работает

Откройте новую вкладку терминала (не закрывая первую!) и введите:

```bash
docker ps
```

Вы должны увидеть два контейнера:

```
CONTAINER ID   IMAGE                    STATUS
abc123def456   postgres:15-alpine       Up (healthy)
xyz789ghi012   sanepidcenter-app        Up (health: starting)
```

**Статус "Up"** означает, что контейнер работает! ✅

### Шаг 5: Откройте приложение в браузере

Откройте любой браузер (Chrome, Firefox, Safari) и перейдите по адресу:

```
http://localhost:8080
```

Или проверьте работоспособность сервиса:

```
http://localhost:8080/actuator/health
```

Если вы видите ответ вроде:
```json
{"status":"UP"}
```

**Поздравляю!** 🎉 Ваше приложение работает!

## 🔧 Часть 5: Управление приложением

### Как остановить приложение

Вернитесь в терминал, где запущено приложение (где бегут логи), и нажмите:

```
Ctrl + C
```

Затем введите:

```bash
docker compose down
```

**Что делает эта команда:**
- Останавливает все контейнеры
- Удаляет их (но не удаляет данные базы!)

### Как запустить приложение снова (после остановки)

```bash
docker compose up
```

(без `--build`, потому что приложение уже собрано)

### Как посмотреть логи (историю сообщений)

```bash
docker compose logs
```

Или только логи приложения:

```bash
docker compose logs app
```

Или только логи базы данных:

```bash
docker compose logs postgres
```

### Как следить за логами в реальном времени

```bash
docker compose logs -f
```

Клавиша `-f` означает "follow" — следовать за новыми сообщениями.

Для выхода нажмите `Ctrl + C`.

## 🗄️ Часть 6: Работа с базой данных

### Что такое база данных в нашем случае?

Наше приложение использует **PostgreSQL** — это популярная система управления базами данных. Представьте её как очень умную таблицу Excel, где:

- Есть несколько листов (таблиц): `profiles`, `organizations`, `inspections`, `violations`
- Каждая таблица имеет строго определённые столбцы
- Данные связаны между собой

### Где хранятся данные?

Данные базы данных хранятся в **томе** (volume) под названием `postgres_data`. Это специальное место на вашем компьютере, которое сохраняется даже после удаления контейнеров.

**Хорошая новость:** Если вы остановите приложение и запустите снова, все данные останутся на месте!

### Как подключиться к базе данных напрямую

Если хотите посмотреть, что внутри базы:

```bash
docker exec -it sanepidcenter-db psql -U postgres -d sanepidcenter_db
```

Вы увидите приглашение вида:
```
sanepidcenter_db=#
```

Теперь можно выполнять SQL-команды. Например, посмотреть все таблицы:

```sql
\dt
```

Или посмотреть данные из таблицы организаций:

```sql
SELECT * FROM organizations;
```

Для выхода из базы данных введите:

```sql
\q
```

## 🧹 Часть 7: Полная очистка (если что-то пошло не так)

### Сценарий 1: Просто перезапустить всё

```bash
# Остановить и удалить контейнеры
docker compose down

# Запустить заново
docker compose up --build
```

### Сценарий 2: Полная очистка (включая базу данных)

⚠️ **Внимание!** Эта команда удалит ВСЕ данные базы данных!

```bash
# Остановить контейнеры и удалить тома с данными
docker compose down -v

# Запустить заново (база будет создана с нуля)
docker compose up --build
```

### Сценарий 3: Очистка всех образов Docker (радикальный метод)

Если хотите освободить место на диске:

```bash
# Удалить все неиспользуемые образы
docker image prune -a
```

Вас спросят подтверждение — введите `y` и нажмите Enter.

## ❓ Часть 8: Частые проблемы и их решение

### Проблема 1: "Port 8080 is already in use"

**Ошибка:**
```
Error starting userland proxy: listen tcp 0.0.0.0:8080: bind: address already in use
```

**Что значит:** Порт 8080 уже занят другой программой.

**Решение:**

Вариант А — Найти и закрыть программу, занимающую порт:

**Windows:**
```bash
netstat -ano | findstr :8080
```
Запомните число справа (PID), затем откройте Диспетчер задач и завершите процесс с этим PID.

**Mac/Linux:**
```bash
lsof -i :8080
```
Запомните PID и выполните `kill -9 <PID>`

Вариант Б — Изменить порт в `docker-compose.yml`:
1. Откройте файл `docker-compose.yml`
2. Найдите строку `"8080:8080"`
3. Замените на `"8081:8080"`
4. Сохраните и запустите `docker compose up --build`
5. Приложение будет доступно по адресу `http://localhost:8081`

### Проблема 2: "Cannot connect to the Docker daemon"

**Ошибка:**
```
Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
```

**Что значит:** Docker не запущен.

**Решение:**

**Windows/Mac:**
1. Откройте программу **Docker Desktop**
2. Дождитесь, пока появится статус "Engine running"
3. Попробуйте команду снова

**Linux:**
```bash
sudo systemctl start docker
```

### Проблема 3: Приложение долго не запускается

**Симптомы:** Видите сообщения, но приложение не появляется через 15+ минут.

**Возможные причины:**
- Медленный интернет (долгая загрузка образов)
- Мало оперативной памяти
- Старый компьютер

**Решение:**
1. Проверьте, сколько свободной памяти:
   ```bash
   docker stats
   ```
2. Закройте лишние программы
3. В Docker Desktop увеличьте лимит памяти (настройки → Resources → Memory → 4GB+)
4. Перезапустите: `docker compose down` и `docker compose up --build`

### Проблема 4: Ошибка при сборке "gradlew not found"

**Ошибка:**
```
/bin/sh: ./gradlew: not found
```

**Что значит:** Не хватает файла сборщика.

**Решение:**
Убедитесь, что в папке есть файл `gradlew`. Если нет — скопируйте его из репозитория проекта.

### Проблема 5: Контейнер постоянно перезапускается

**Симптомы:** В `docker ps` видите статус "Restarting".

**Решение:**
Посмотрите логи, чтобы понять причину:
```bash
docker compose logs app
```

Частые причины:
- База данных ещё не готова (подождите 1-2 минуты)
- Неправильные настройки подключения (проверьте `docker-compose.yml`)
- Ошибка в коде приложения

## 📊 Часть 9: Дополнительная информация

### Какие сервисы запускаются?

Наше приложение состоит из двух частей:

1. **PostgreSQL (база данных)**
   - Имя контейнера: `sanepidcenter-db`
   - Порт: 5432
   - Хранит все данные приложения

2. **Spring Boot Application (само приложение)**
   - Имя контейнера: `sanepidcenter-app`
   - Порт: 8080
   - Обрабатывает запросы пользователей

### Как они связаны?

```
┌─────────────────┐
│   Веб-браузер   │
│  (вы в нём)     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐      ┌─────────────────┐
│   Приложение    │─────▶│  База данных    │
│   (порт 8080)   │◀─────│  (порт 5432)    │
└─────────────────┘      └─────────────────┘
```

Приложение получает запросы от вас через браузер, обрабатывает их и сохраняет/читает данные из базы.

### Что такое "здоровье" (healthcheck)?

В файле `docker-compose.yml` вы могли заметить блок `healthcheck`. Это механизм проверки, работает ли сервис нормально.

**Для базы данных:**
- Проверяется командой `pg_isready`
- Если база отвечает — статус "healthy"

**Для приложения:**
- Проверяется запросом к `/actuator/health`
- Если приложение отвечает — статус "healthy"

Вы можете видеть статус здоровья в команде `docker ps` в колонке STATUS.

## 🧪 Тестовые данные для всех POST-запросов API

> Важно: в POST-телах **не нужно** передавать `createdAt` и `updatedAt` — эти поля заполняются автоматически на сервере.

### 1) Логин
```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin1",
    "password": "admin1"
  }'
```

### 2) Регистрация пользователя
```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "inspector_test",
    "password": "test123",
    "fullName": "Тестовый Инспектор",
    "phone": "+79990001122",
    "position": "Инспектор",
    "role": "ROLE_INSPECTOR"
  }'
```

### 3) Создание организации
```bash
curl -X POST http://localhost:8080/api/organizations \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ООО Тест Питание",
    "shortName": "ТестПит",
    "registrationNumber": "REG-2026-001",
    "type": { "id": 1 },
    "address": "г. Москва, ул. Тестовая, 1",
    "city": "Москва",
    "directorName": "Иванов И.И.",
    "phone": "+74951234567",
    "email": "test-org@example.com",
    "employeeCount": 55,
    "riskCategory": "medium",
    "notes": "Тестовая организация"
  }'
```

### 4) Создание проверки
```bash
curl -X POST http://localhost:8080/api/inspections \
  -H "Content-Type: application/json" \
  -d '{
    "organization": { "id": "00000000-0000-0000-0000-000000000001" },
    "type": { "id": 1 },
    "inspector": { "id": "00000000-0000-0000-0000-000000000010" },
    "scheduledDate": "2026-05-15",
    "status": "planned",
    "result": "pending",
    "findingsSummary": "Проверка запланирована",
    "recommendations": "Подготовить документацию",
    "actNumber": "ACT-2026-001"
  }'
```

### 5) Создание нарушения
```bash
curl -X POST http://localhost:8080/api/violations \
  -H "Content-Type: application/json" \
  -d '{
    "inspection": { "id": "00000000-0000-0000-0000-000000000100" },
    "code": "V-001",
    "description": "Нарушение санитарных норм",
    "severity": "major",
    "articleReference": "СанПиН 2.3/2.4",
    "correctionDeadline": "2026-06-01",
    "resolved": false,
    "resolutionNotes": "Ожидается устранение"
  }'
```

### 6) Admin: создание пользователя (только для ROLE_ADMIN)
```bash
curl -X POST http://localhost:8080/api/admin/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <JWT_ADMIN_TOKEN>" \
  -d '{
    "username": "lab_user_1",
    "password": "lab123",
    "fullName": "Лаборант Тестовый",
    "phone": "+79991112233",
    "position": "Лаборант",

    "isActive": true
  }'
```
